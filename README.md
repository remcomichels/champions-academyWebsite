# 📘 Nuxt 4 Template — Storyblok + i18n + SEO + HTTPS Dev

This project is a **modern Nuxt 4 application template** pre-configured with a flexible CMS-driven architecture using **Storyblok**, **Nuxt SEO**, **Nuxt Image**, **i18n**, GSAP, Lenis, HTTPS local development, and a clean UI system.

Ideal for:

- Landing pages
- Corporate websites
- Multi-language sites
- CMS-driven content projects
- Agencies and freelancers who need a strong base template

---

## ✨ Features Overview

### 🧱 Core Stack
- **Nuxt 4** (server-rendered SPA / universal app)
- **Storyblok** (headless CMS with Visual Editor)
- **@nuxtjs/i18n** (internationalization)
- **@nuxtjs/seo** (sitemap, OG tags, meta management, Schema.org)
- **Nuxt Image** (Storyblok provider)
- **Nuxt Fonts**
- **Nuxt Icon**
- **Nuxt Scripts**
- **VueUse**
- **GSAP + Lenis for animations and smooth scrolling**
- **HTTPS local development support**

## 🔧 Installation & Setup

### 1. Install dependencies
```
npm install
```

### 2. Create `.env`
```
NUXT_STORYBLOK_API_KEY=your_storyblok_token
```

### 3. HTTPS Certificates for Local Development
Place your certificates in:

```
keys/localhost.pem
keys/localhost-key.pem
```

Or change the dev script to plain HTTP.

## 🧩 Storyblok Integration

### Component Rendering
Storyblok content resolves dynamically via:

```vue
<StoryblokComponent :blok="story.content" />
```

### Bloks Folder
All blocks live inside:

```
/storyblok
```

Automatically mapped to CMS components.

### Example Bloks
- `page.vue`
- `hero.vue`
- `grid.vue`
- `feature.vue`
- `teaser.vue`

### Routing
- **Single catch-all page:** `pages/[...slug].vue`
  - Fetches Storyblok stories (draft mode, locale aware).
  - Resolves relations.
  - Throws Nuxt errors on missing/failed stories.
  - Defines OpenGraph images via `defineOgImageComponent`.

### UI System
- **Global layout:** `layouts/default.vue`
  - Adds `<NuxtHeader />` + `<NuxtFooter />` around every page.
- **Global LESS:**
  - `assets/less/main.less` + auto-injected variables & mixins in Vite.
- **Components:**
  - `/components` (Standard Vue components)
  - `/storyblok` (Mapped 1:1 to Storyblok components)
- **Smooth UX:** Powered by **GSAP**, **ScrollTrigger**, and **Lenis**.

```
/components
```

## 🧬 Generated Types

Two type files are generated from a live schema rather than written by hand, so
they cannot drift from the thing they describe. Re-run the command after
changing a block in Storyblok or a table in Supabase, and commit the result.

```bash
npm run types:supabase    # Supabase public schema → server/types/supabase.d.ts
npm run types:storyblok   # Storyblok block schema → storyblok.gen.d.ts (path printed by the CLI)
```

Both need a one-time login (`supabase login`, `storyblok login` — the Storyblok
CLI also accepts `STORYBLOK_LOGIN` / `STORYBLOK_TOKEN` from `.env` for CI) and
an id in `.env`: `SUPABASE_PROJECT_REF` and `STORYBLOK_SPACE_ID`. Neither id is
read by the app itself, only by these two commands.

The Supabase types live under `server/` because nothing in the browser talks
to the database — `db()` in `server/utils/supabase.ts` is typed with them, so a
wrong column or table name is a build error.

The Storyblok types are generated as `storyblok.gen.d.ts` so they cannot
overwrite the hand-written `app/types/storyblok.ts`. Those two still need
reconciling — the hand-written file has drifted (13 templates read
`blok.anchor`; 3 interfaces declare it).
